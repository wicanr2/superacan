# soundregprobe：UM6619 暫存器回讀掃描

65C02 對每個暫存器寫一次 `$5A` 再讀回，把回讀值存進 sound RAM `$0700+n`；68k 每幀把
256 個值當成 tile 編號填進 ROZ 的 16×16 版面。tile n 整塊填索引 n、調色盤又把索引編回
它自己，所以截圖能直接反推每一格讀到什麼。

結論寫在 [../../docs/sound-driver.md](../../docs/sound-driver.md) §6.1。

## 版權邊界

授權區 `$2000–$23FF` 建置時由**使用者自己的 ROM** 取出，產物 `build/*.bin` 只留本機。

## 建置

```sh
python3 build.py --auth-rom "../../Bcan008b/ROMS/Boom Zoo (Taiwan).bin"
```

| 參數 | 用途 |
|---|---|
| `--data` | 寫進每個暫存器的值（預設 `$5A`）|
| `--last-reg` | 只掃到這個編號，用來二分定位 |
| `--skip` | 跳過的暫存器，預設 `$17` |
| `--release` | `0` 讓 65C02 保持重置，用來確認 68k 側是否正常 |

## 為什麼要跳過 `$17`

第一版沒有跳過任何暫存器，Bcan 直接黑屏。二分（`--last-reg` 逐次收斂：`$0F` 正常、
`$17` 停住、`$15`／`$16` 正常）定位到 **`$17`**，那是 key on/off。寫 `$5A` 會把參數
還是垃圾的通道 key on，Bcan 的邊界保護就整台「安全停止」。**這不是「未知暫存器」，
是取樣越界。**

`--release 0`（65C02 保持重置）能畫出綠底，證明 68k 側沒問題——這一步是把「ROM 有問題」
與「聲音側有問題」分開的關鍵，不然黑屏什麼都看不出來。

## 結果（2026-09-02）

跳過 `$17` 之後兩邊都掃得完，而且顏色分布完全相同。逐格比對：

| 暫存器 | Bcan 回讀 | 本專案回讀 |
|---|---|---|
| `$14` | `$1A`（bit 6 被清掉）| `$5A` |
| `$16` | `$5A` | `$1A`（bit 6 被清掉）|
| `$17` | 跳過 | 跳過 |
| 其餘 254 個 | `$5A` | `$5A` |

兩件事：

1. **除了一個暫存器之外，Bcan 對全部 256 個編號都只是單純存放。** 原本待查證的
   `$40–$4E`（通道模式）與 `$A0–$DF`（envelope）在 Bcan 裡沒有任何額外行為，
   **它不能當這些暫存器語意的 oracle**。
2. **哪一個暫存器「讀回值會少 bit 6」，兩邊接的不是同一個**：Bcan 是 `$14`、本專案是
   `$16`。本專案的 `$16` 行為有遊戲驅動的 IRQ ack 證據支持，Bcan 的 `$14` 目前只有這一筆
   量測。兩者沒有合併，維持記錄差異。
