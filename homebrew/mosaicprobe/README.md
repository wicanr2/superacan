# mosaicprobe：一般圖層與 ROZ 的 mosaic 量測卡帶

畫面鋪滿 16 像素週期的解碼圖樣，用來回答一個問題：mosaic 欄位造成的塊大小是
**欄位值 + 1**，還是 `2^欄位值`？兩種模型在欄位值 ≥ 2 時的差異大到整片畫面都不一樣，
所以一張截圖就能定案。

結論與查表內容寫在 [../../docs/tilemap-format.md](../../docs/tilemap-format.md)，
本檔只記怎麼跑、怎麼判讀。

## 版權邊界

映像的 `$2000–$23FF` 是卡帶授權區（1024 bytes，八款流通 ROM 完全相同），建置時由
**使用者自己的 ROM** 取出。產物 `build/*.bin` 因此含有版權資料：只留本機，不進版控。

## 建置與執行

```sh
for m in 3 5; do
  python3 build.py --auth-rom "../../Bcan008b/ROMS/Boom Zoo (Taiwan).bin" --mosaic $m --layer tile
done
for m in 3 6; do
  python3 build.py --auth-rom "../../Bcan008b/ROMS/Boom Zoo (Taiwan).bin" --mosaic $m --layer roz
done
```

建置時會印出兩種模型各自預測的塊大小，可直接與截圖對照。
Bcan 端的操作方式（不吃命令列 ROM 參數、要走 GUI）見 `../bit3probe/README.md`。

## 判讀

來源圖樣的像素值 ＝ `(x&7) + 8×(y&7) + 64×t`，`t` 由 tile 在 2×2 區塊中的位置決定；
調色盤把三個分量分別編進紅、綠、藍。所以截圖上每個像素都能反推它取樣自來源的
哪一格，塊大小與塊原點是量出來的，不是從外觀猜的。

比對時要同時算四種模型的不符像素數：查表、位元遮罩、只量化 X、只量化 Y。
只報「查表模型差 0」沒有意義——要看見另外三個模型差幾萬個像素，才知道那個 0 不是恆真。

## 結果（2026-09-02）

| 映像 | 查表 `floor(d/(m+1))×(m+1)` | 位元遮罩 `2^m` | 只量化 X | 只量化 Y |
|---|---:|---:|---:|---:|
| `--layer tile --mosaic 3` | **0** | 57,600 | 57,600 | 57,600 |
| `--layer tile --mosaic 5` | **0** | 75,540 | 64,000 | 63,840 |
| `--layer roz --mosaic 3` | **0** | 57,600 | 57,600 | 57,600 |
| `--layer roz --mosaic 6` | **0** | 76,359 | 65,600 | 65,760 |

分母是整張畫面 76,800 個像素。四顆映像在 Bcan 0.0.8b 與本專案 Linux 重製上逐像素相同。
