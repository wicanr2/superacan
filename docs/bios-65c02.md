# 65C02 端韌體（internal_6502_1/2.bin）分析

> 來源：**(a)** 級——對 `Bcan008b/bios/supracan.zip` 內兩檔的內容統計與
> 相關性分析（2026-08-30）；MAME `src/mame/umc/supracan.cpp` 的載入方式
> 與註解 **(b)**；卡帶 ROM 行為驗證 **(a)**。

## 1. 結論先行：這兩塊不是 65C02 程式，是聲音取樣資料

| 檔案 | 區域 offset | 映射到 sound RAM | 內容 |
|---|---|---|---|
| internal_6502_1.bin | `$0000–$0FFF` | `$0000–$0FFF` | 全 `00`，僅 `$040F` = `$08`（(b) 註解一致） |
| internal_6502_1.bin | `$1000–$1FFF` | `$1000–$1FFF` | 取樣資料（約 4042 個非零位元組） |
| internal_6502_2.bin | `$0000–$1FFF` | `$2000–$3FFF` | 取樣資料 |

證據：

1. **映射方式 (b)**：MAME 把兩檔載入 `internal6502` region（16 KB），
   `machine_reset()` 時 `std::copy_n(internal6502, 0x4000, soundram)` ——
   **整塊複製進 65C02 的共享 sound RAM `$0000–$3FFF`**，不是獨立 ROM
   位址空間。這解釋了 bios-rom-format.md §1.2 的舊疑問：檔尾不像向量，
   因為根本沒有向量——它們不是開機程式。
2. **內容統計 (a)**：8-bit 有號數列的相鄰取樣平均絕對差：檔 2 為 26.9、
   檔 1 `$1000+` 為 58.0，對洗牌後的 ~105 有強烈相關性 → 典型音訊取樣
   特徵，不是程式碼。MAME 註解 (b) 亦直接稱 `$1000–$3FFF` 為 samples，
   並記 BIOS/開機流程只用到 `$2E00–$2EFF` 一小段。
3. **IPL 不碰音效 (a)**：68k IPL（見 [bios-68k.md](bios-68k.md)）全程不
   寫 `$E80000` sound RAM、不解除 65C02 的 HALT（`$E9001C` bit0 保持 0）
   → 開機階段 65C02 根本不跑。

推測用途（**待查證**）：主機內建開機音效（卡帶開機動畫播放 A'Can 標誌
音）用的內建取樣庫，遊戲可直接播放 sound RAM 內既有取樣。

## 2. 65C02 的實際開機流程（(a)+(b)）

65C02 的程式**全部由卡帶（68k 端）提供**：

1. 68k 把 65C02 代碼經 `$E80000` 視窗寫入共享 sound RAM（68k 端 16-bit
   存取、byte 對調寫入 65C02 端，見 memory-map.md §2）；含在 `$FFFA–
   $FFFF` 放置 NMI/RESET/IRQ 向量。
2. 68k 寫 `$E9001C` bit0 = 1 解除 65C02 的 HALT/reset。
3. 65C02 從 sound RAM 內的 reset 向量起跑，整個 64 KB 空間對映同一塊
   sound RAM（I/O 在 `$0400–$04FF` 攔截）。

驗證 (a)：8 款流通 ROM 全部含有對 `$E9001C`（3–12 處）與 `$E80000`
視窗（5–215 處）的存取碼，符合「卡帶上傳音效程式」模型。

## 3. 68k ↔ 65C02 通訊協定（(a)+(b)，後續遊戲碼已驗證）

| 方向 | 機制 |
|---|---|
| 68k → 65C02 | 經 `$E80000` 直接讀寫 sound RAM；主命令串位於 `$0300`，寫 `$E9000A` 觸發 65C02 IRQ bit5，65C02 讀 `$040A` 作專屬 ack；另可經 `$E80404/$E80405` 寫 latch 並觸發 bit3／bit2，65C02 分別讀 `$0404/$0405` ack |
| 65C02 → 68k | 寫 `$040A` 觸發 68k **IRQ6**（mailbox）；68k 另可從 sound RAM `$0200/$0202` 直接讀已組合的手把狀態 |
| 手把 | 65C02 負責序列移位掃描（`$0407` 控制、`$0402/$0403` 讀出），組合後放 sound RAM 供 68k 讀 |
| DMA 播放 | UM6619 取樣 DMA 的位址由 65C02 經 host port（`$E90000` 區，`$0404+` 讀取）交給 68k 端；IRQ 來源 bit6（`0x40`）= DMA 取樣播放完成 |
| UM6619 | 間接定址：`$0420` 寫暫存器位址、`$0422` 讀寫資料 |

→ **音效驅動結構本體在卡帶程式裡**，兩塊「6502 BIOS」只是資料。後續已以
Speedy Dragon 與 Boom Zoo 的上傳程式驗證主要命令、latch、IRQ ack、手把與
取樣 DMA 資料流；固定原始位址與仍未知欄位見 [sound-driver.md](sound-driver.md)。

## 4. 時脈

本節原先因兩檔不含程式碼而只能引用 MAME 的未定案分頻。後續 Bcan 0.0.8b
反編譯確認 master tick 為 107.38635 MHz、65C02 每 30 tick 執行一次，故時脈為
**3.579545 MHz（a）**；這項新證據推翻 MAME `U13/6/2` 約 4.47 MHz 的猜測。
完整計算與 68k 對照見 [memory-map.md](memory-map.md#1-時脈a-定案推翻-b)。
