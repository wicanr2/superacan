# 遊戲上傳的 65C02 音效驅動與音訊通訊協定

> 來源：**(a)** 級——對 `Bcan008b/ROMS/Speedy Dragon (Taiwan).bin` 與
> `Boom Zoo (Taiwan).bin` 的 68k/65C02 反組譯（2026-08-30，word-swap 還原後
> 以 Capstone M68K / MOS65XX(65C02) 反組譯；IDA 9.4 授權不含 mc68k/m65 模組，
> 未使用）。MAME driver 對照 **(b)**。
> 所有 68k 位址為 ROM 映像 offset（= 匯流排位址，卡帶映射於 `$000000` 起）；
> 65C02 位址為 sound RAM 位址。

## 0. sound RAM 窗口的位元組序 (a)

68k 經 `$E80000` 窗口存取 65C02 sound RAM 時**不做位元組交換**：
68k `$E80000+n` 即 65C02 `$n`（byte 與 word 存取皆然）。
證據：

1. Speedy Dragon 以 `move.w (a0)+,(a1)+` 迴圈上傳 65C02 驅動，ROM 內
   65C02 映像（word-swap 還原後）**不加交換**即為正確 65C02 碼，reset 向量
   正確落在映像尾。
2. 65C02 端開機完成時寫 `$0300=$FF`；68k 端以 `cmpi.b #$FF,$E80300`
   （偶位址 byte 讀取）等待——兩邊位址一致。
3. Boom Zoo / Speedy Dragon 的命令串以未交換位元組序解析才合理（§4）。

word-swap 只存在於 **ROM 檔案格式**層，不存在於這個硬體窗口。MAME `_68k_soundram_w`
也是直接 big-endian 拆寫（`soundram[offset*2] = data >> 8`），與此一致。

## 1. 上傳機制

### 1.1 Speedy Dragon（開機驅動，直接複製）(a)

- 68k 入口 `$C4A`：`$E9001C=0`（HALT 65C02）→ 以 word 迴圈把 ROM
  **`$556A` 起 0x1000 bytes** 複製到 `$E8F000`（= 65C02 `$F000–$FFFF`，
  含 `$FFFA–$FFFF` 向量）→ `$E80300=0` → `$E9001C=1` 釋放。
- 65C02 向量：NMI=`$F4A8`、RESET=`$F000`、IRQ=`$F4B1`；另有 RAM 向量表
  `$FFEC–$FFF8`（IRQ 來源分派用，§3）。
- 開機完成後 65C02 寫 `$0300=$FF`；68k 端輪詢等待（帶逾時計數）。

### 1.2 Speedy Dragon（第二塊，DMA 上傳）(a)

- **實際執行的上傳常式是 `$34E4`**（2026-08-31 superacan-emu 里程碑 3 執行期
  追蹤確認；`$954` 靜態碼中的 control `$2648` 無任何呼叫者，為未使用的舊碼）：
  - `$34E4`：`$E9001C &= ~1`（HALT 65C02）→ 主機 DMA ch0：src=`$3D6A`、
    dest=`$E8E800`、count=`$BFF`、control=**`$B800`**（bit15 觸發＋word 模式，
    共 0x1800 bytes → 65C02 `$E800–$FFFF` 含向量區）→ `clr.w $E80300`
    → `$E9001C |= 1` 釋放 → **立即 `jsr $28DE`** 送命令（空命令串）並等
    `$0300=$FF`（逾時 `$C000` 次 ≈ 0.2 秒，逾時則呼叫 `$34C6` 整組重試）。
  - 呼叫鏈：`$34C6`（逾時/初始化入口）→ `$34E4`（上傳+boot 握手）→
    `$3536`（歌曲資料 DMA）→ `$364C`。
- 因此第二驅動的 boot 握手有**嚴格時序要求**：68k 釋放 65C02 後立刻送命令，
  65C02 必須在約 0.2 秒內完成 init（見 §2.2 的 probe）並 ack。模擬器若讓
  probe 走完整逾時迴圈（≈0.2 秒）會剛好超過 68k 逾時 → 無限重試迴圈
  （superacan-emu 實測並修正，見 §3 latch 說明）。
- ROM `$4000` 起的獨立 65C02 程式（內部參照 `$E8xx–$F2xx`）即此映像
  （`$3D6A` 起 0x1800 bytes）；向量：NMI=`$ED61`（→`jmp ($FD50)`=`$ED64`）、
  RESET=`$E802`、IRQ=`$ED75`。結構見 §2.2。

### 1.3 Boom Zoo（壓縮上傳）(a)

- 常式 `$2624`：`$E9001C=0` → 清 `$E8040A`（65C02 `$040A` IRQ 請求）→
  `jsr $2B22` 從 ROM **`$F40`** 解壓縮到 Work RAM `$FC0000/$FC0800` →
  DMA ch0：`$FC0800→$E8F000`、count `$7FF`、control `$9800`（word 模式，
  共 0x1000 bytes → 65C02 `$F000–$FFFF`）→ `$E80300=0` → `$E9001C=1`
  → `jsr $27D0` 等 `$0300=$FF`。
- 解壓縮器 `$2B22`（自訂格式）：串流由 chunk 組成，每 chunk = tag byte
  + 跳過 1 byte + 16-bit BE 長度；tag `$F1`=RLE 游程（控制 byte >$BF 時
  低 6 bit 為重複次數）、`$F3`=自帶 Huffman 表（表前跳過 `$A4` bytes）、
  `$F4`=用內建表（`$3040`）、其他=literal 複製。
- Boom Zoo 68k 端命令協定（§4）與 Speedy 開機驅動**完全一致**，
  推測解壓出來的是同一族驅動（**待查證**，未實作解壓器驗證）。

## 2. 65C02 驅動結構（Speedy 開機驅動，ROM $556A → $F000）(a)

- **RESET `$F000`**：sei、設堆疊、`jsr $F7DC` 初始化，之後進入主迴圈：
  逐通道（zp `$2A` 為通道索引，最多 `$FB8C`=15 個）檢查 `$0270,y`
  （通道啟用旗標）、用 zp `$14/$15+2ch` 的串流指標讀序列資料
  （`$F39B` = 讀 byte 並遞增指標），依 `$0278,y` bit4-6 經表 `$FA7C`
  分派通道狀態處理（`$F0BE/$F241/$F24C/$F257/$F29C`）。
- **初始化 `$F7DC`**：清 zp/`$0200`/`$0300` 頁；UM6619 初始化（reg `$17`
  遞增寫入、regs `$40–$4E`=3、依表 `$F7CE` 寫 `$EF=$FF,$AF=$80,$14=$CF,
  $13=$90,$12=$F9,$11=$02,$07=$80`）；`$F81B` 設 IRQ enable（`$0410`）並
  探測手把；最後 `$F99F`：寫 `$0300=$FF`（boot OK），若 zp `$3A`≠0 則
  寫 `~$3A` 到 `$040A` 通知 68k。
- **IRQ `$F4B1`**：讀 `$0411`（讀取即清）分派——
  bit6(`$40`)→`$F64A` 取樣 DMA；bit2(`$04`)→`$F4F1` latch `$0405`；
  bit3(`$08`)→`$F53F` latch `$0404`；bit4(`$10`)→`$F58F` 讀 `$0409` ack；
  bit5(`$20`，68k 請求)→`$F595` 命令分派；bit7(`$80`，timer)→`$F620`。
- **NMI `$F4A8`** → `jmp ($FFEC)` → `$F4AB`：讀 `$0412` ack 後 rti。
  NMI 來源是主機端 vblank：MAME 在 vpos 240、`$E90010` bit7 成立時同時拉 68k IRQ7 與
  65C02 NMI（driver 註「staiwbbl requires this for inputs to work」），見
  [memory-map.md](memory-map.md) §6。
- **timer tick `$F620`**：讀 UM6619 reg `$14` 測 bit6（DMA/計時模式），
  寫 `$8F`/`$4F` 回 reg `$14`；音樂逐拍更新在 `$F3E6` 起（通道 duration
  計數 `$02C0/$02D0` 遞減、歸零 key-off、音量漸變寫 reg `$E0|ch`）。
  → 音樂 tempo 由 UM6619 內建 timer 驅動。
- **手把掃描 `$F87E`**：timer 每 5 tick 一次（計數器 `$FBA1`）。
  `$0407` 寫 `$08`（P1）/`$04`（P2）脈衝 8 次移位，從 `$0403`/`$0402`
  讀回，經位元重排（`$F94A`）後取反存入 **`$0200/$0201`（P2?）與
  `$0202/$0203`（P1?）**——即 68k 直接從 sound RAM `$0200/$0202` 讀手把
  的機制 (b) 由此證實。`$023E` bit0/bit1 = 手把 presence（開機時以
  `$0406`/`$0407=$30` 探測）。
- **數學常式**：`$F733` 32-bit 除法、`$F77A` 32×16 乘法、`$F7B4` 8×8
  乘法（音高/音量計算用）。
- 通道工作區：每通道 64 bytes，基址 `$FBA2`+ch×64（`$F21B`）；共用陣列
  在 `$0250–$02F0`（各 16 bytes 一欄：串流指標、duration、旗標等）。

## 2.2 第二套驅動結構（Speedy 音樂驅動，ROM $3D6A → $E800）(a)

> 2026-08-31 superacan-emu 里程碑 3：Capstone 65C02 反組譯 + 模擬器執行期
> 追蹤。此驅動在 superacan-emu 上已可完整跑通（boot ack、命令分派、音樂播放）。

- **向量**：NMI=`$ED61`（→`jmp ($FD50)`=`$ED64`：手把掃描 `$F90C`，
  讀 `$0412` ack 後 rti；NMI 來源為主機 vblank，見 §2 與 memory-map.md §6）、
  RESET=`$E802`、IRQ=`$ED75`。
- **RESET `$E802`**：sei、設堆疊、`jsr $F093` init，之後 `$E809` 主迴圈前
  等待 `$FE77==0`（由命令 handler `$F397` 依命令碼 & 6 控制：`==4` 時清
  `$FE77` 放行）——即 68k 上傳後還要送一條「模式」命令才真正進主迴圈。
- **init `$F093`**：清 zp 與 `$0200` 頁 → 16 通道 key-off（reg `$17` 遞增寫）
  → UM6619 init（`$07=$80`、`$13=$90`、`$14=$CF`）→ probe `$F0D3`
  （IRQ enable=`$0C`、寫 `$0406=3`、`$0407=$30` 清除脈衝、等 `$023D==0`，
  逾時 256×256 迴圈；依結果清 latch IRQ enable）→ `$0409=6`、
  enable `|= $F2` → boot ack `$F083`（`$0300=$FF`，若 `$FE76`≠0 寫
  `~$FE76` 到 `$040A` 通知 68k）。
- **IRQ 分派 `$ED75`**：讀 `$0411`（**純狀態、不清除**，見 §3）後依位移到
  間接向量表 `$FD52`：bit2→`$EDB3`（latch `$0405`）、bit3→`$EDFC`
  （latch `$0404`）、bit4→`$EE90`（讀 `$0408` ack）、bit5→`$EE96`
  （**命令分派**）、bit6→`$EF38`（取樣 DMA）、bit7→`$EF02`（timer：
  讀 reg `$14` ack、`$FE78` 相關、寫 `$8F`/`$4F` 回 reg `$14`）。
- **命令分派 `$EE96`**：串流指標 zp `$02/$03`=`$0300`、先讀 `$040A` ack
  bit5；命令 byte `<$70` 經表 `$FE1C`（至少 40 個 entry，涵蓋通道啟停/
  取樣播放/全域控制，逐一對應待整理）、`≥$70` 走 `jmp ($0008)` 特殊路徑；
  讀到 `$00` 結束，`$F083` ack。
- 主迴圈（`$E81F` 起）：逐 slot（zp `$67` 索引、指標表 zp `$A0+2n`）讀串流
  （`$EEEC`），值 `≥$20` 走 `$F6F9`（通道處理），`<$20` 經表 `$FE1C` 分派。

## 3. I/O 埠使用（65C02 端，(a) 實測驅動碼）

| 位址 | 驅動中的實際用途 |
|---|---|
| `$0300` | **mailbox/命令緩衝**：68k 寫命令串於此；65C02 處理完寫 `$FF` 作為 ack（68k 輪詢） |
| `$0200/$0202` | 手把 1/2 狀態（active low，68k 直接讀） |
| `$0402/$0403` | 手把 shift register 讀出（P2/P1） |
| `$0404/$0405` | 68k→65C02 byte latch ×2（IRQ bit3/bit2）；**空讀回 `$CD`**、bit7=有資料、bit6=重設索引；各收滿 3 bytes 解碼（第一驅動 `$F5D5`、第二驅動 `$EE47`，見 §4.3）。68k 端經 `$E80404/$E80405` 窗口寫入（寫入即置位並觸發 IRQ）；65C02 讀取即 ack 對應 IRQ 並清空 |
| `$0406` | 手把 presence 探測（寫 3，讀回清 bit） |
| `$0407` | 手把移位控制：寫 `$08`/`$04` 脈衝移位、寫 `$30` 探測（清除脈衝會觸發 latch IRQ，probe 藉此讀到 `$CD` 快速結束——觸發條件為功能推測 (a)，見 superacan-emu/docs/verify-audio-input.md） |
| `$0408` | 第二驅動中讀取（IRQ bit4 handler `$EE90`），功能待查證 |
| `$0409` | IRQ bit4 來源 ack（讀） |
| `$040A` | 65C02→68k IRQ 請求（寫任意值觸發 68k IRQ6）；**65C02 讀取 = ack IRQ bit5**（兩套驅動的 bit5 handler 都讀它）；**68k 寫 `$E9000A` 則觸發 65C02 IRQ bit5**（命令通知） |
| `$040C/$040D` | 取樣 DMA 位址/狀態交給 68k 端（寫後立刻寫 `$040A=$FF` 通知 68k refill，見 §4.4） |
| `$0410` | IRQ enable（bit0-3 = latch/手把相關、bit4-7 = timer/DMA/68k 請求等） |
| `$0411` | IRQ 來源旗標，**純狀態、讀取不清**（(a)，superacan-emu 實測）——各 bit 由專屬 ack 拉住直到清除：bit2←讀 `$0405`、bit3←讀 `$0404`、bit4←讀 `$0409`、bit5←讀 `$040A`、bit6←讀 UM6619 reg `$16`、bit7←讀 reg `$14`。證據：兩套驅動的 dispatcher 都只用一次 `$0411` 讀值分派**一個**來源就 rti，依賴 level 重觸發補跑其餘來源；「讀取即清全部」（MAME 行為）會丟同時發生的來源 |
| `$0412` | NMI ack（讀） |
| `$0420` | UM6619 位址埠／狀態（**bit0=busy**：讀寫前後都要輪詢 bit0=0；寫 reg 號後插 6 個 NOP 延遲） |
| `$0422` | UM6619 資料埠 |

`$0420`／`$0422` 的分工由 Bcan 反編譯確認（(a)，`sub_1400A5220`）：寫 `$0420` 只是把
暫存器編號閂進內部欄位，寫 `$0422` 才真的送出「編號＋資料」。

### 6.1 全暫存器回讀掃描（a，2026-09-02）

`homebrew/soundregprobe/` 讓 65C02 對每個編號寫一次 `$5A` 再讀回，把 256 個回讀值畫成
色格。結果：

| 暫存器 | Bcan 回讀 | 本專案回讀 |
|---|---|---|
| `$14` | `$1A`（bit 6 被清掉）| `$5A` |
| `$16` | `$5A` | `$1A`（bit 6 被清掉）|
| `$17` | 掃描時跳過 | 掃描時跳過 |
| 其餘 254 個 | `$5A` | `$5A` |

兩個結論：

1. **254 個編號的回讀值是原樣的，但這不代表寫入沒有副作用。** 回讀掃描只證明
   Bcan 把寫入值存了下來；後續反編譯混音器發現它有一台 MAME 沒有的包絡產生器
   （線性／平方漸變與幾何衰減，見 [emulator-analysis.md](emulator-analysis.md) §4.8），
   所以至少有一部分編號**是有語意的**，只是語意不表現在回讀值上。
   `$40–$4E`（通道模式）與 `$A0–$DF`（envelope）各自對應到哪個欄位仍**待查證**，
   但「Bcan 不能當這些暫存器的 oracle」這個結論不再成立——要改成「回讀掃描這個手段
   看不到它們，要改用反編譯或聽覺／波形比對」。
2. **「讀回值少 bit 6」的那個暫存器，兩邊接的不是同一個**：Bcan 是 `$14`、本專案是
   `$16`。本專案的 `$16` 有遊戲驅動的 IRQ ack 證據支持，Bcan 的 `$14` 目前只有這一筆
   量測。兩者不合併，維持記錄差異。

`$17`（key on/off）必須跳過：寫入會把參數還是垃圾的通道 key on，Bcan 的邊界保護會整台
「安全停止」。這是**取樣越界**，不是未知暫存器——先前推測「Bcan 會把不認得的編號記進
故障報告，可用來列舉」，實測不成立：整趟掃描沒有產生任何 `*.fault.txt`。

UM6619 存取包裝：`$F3AE` = 讀 reg X → A；`$F3C9` = 寫 reg X = A。

## 4. 68k ↔ 65C02 協定

### 4.1 命令通道（主通道）(a)

1. 68k 把命令串寫到 `$E80300` 起（65C02 `$0300`），`$00` 結尾。
2. 68k 寫 `$E9000A`（值為參考用 byte，如命令數/旗標）→ 觸發 65C02 IRQ
   bit5 → `$F595`。
3. 65C02 從 `$0300` 逐 byte 讀（`$F39B`），每個命令 = 1 opcode byte +
   參數，經表 `$FA70` 分派；讀到 `$00` 結束。
4. 65C02 呼叫 `$F99F`：`$0300=$FF` 作 ack；68k 端（如 Speedy `$28DE`、
   Boom Zoo `$27D0`）輪詢 `$E80300==$FF` 後返回。

命令表（`$FA70`，6 條）：

| Cmd | 處理 | 參數 | 功能 |
|---|---|---|---|
| `$00` | — | — | 命令串結束 |
| `$00`→`$FA60`* | `$FA60` | reg, val | UM6619 raw 寫：reg X=byte1、val=byte2（※opcode 0 在串首以外位置仍會被查表執行，實際用作結尾） |
| `$01` | `$F9AE` | ch&#124;flags, ptrHi, ptrLo | **啟動通道**：byte1 bit0-2=通道、bit7=旗標（→`$0260,ch=0`）；接著 16-bit **big-endian** 串流位址寫入通道指標並初始化通道工作區，標記 `$0270/$0280/$0288,ch=$FF` |
| `$02` | `$FA34` | ch&#124;flags | **停止**：byte1 bit0-2=通道，bit7 → `$0270,ch=$FF`（停）/否則清 0；再掃全部通道，`$02A0,x`==byte1 者一併 key-off（群組停止） |
| `$03` | `$F6D5` | aHi, aLo, lenHi, lenLo | **取樣播放**：aHi→reg `$3F`、aLo→reg `$2F`（取樣起始位址）、len→`$36/$37`（16-bit 計數）；依表 `$F6B7` 設 UM6619（regs `$17,$2F,$3F,$4F,$5F,$6F,$7F,$9F,$16`），reg `$9F=$FF`、reg `$16=$80` 啟動 |
| `$04` | `$F706` | — | **停止取樣**：reg `$9F`=0、reg `$17`=`$0F`、reg `$16`=0 |
| `$05` | `$F71C` | mode, val | 全域：byte1→`$3F`（=1 時 `$42`=0，否則 `$42=$0F`）；byte2→`$40/$41`（速度/主音量相關，確切語意待查證） |

Boom Zoo 68k 端範例（對照驗證一致 (a)）：
- 音效初始化 `$27DC`：串 `02 00 02 01 … 02 07`（cmd2 停 ch0-7）+
  `$0310=0`。
- 播放 SFX `$2830`：從音效索引表（指標在 `$FC E0AE`）取 entry
  （word0=長度、word2=65C02 目的位址、word4=ROM 指標），解壓縮 →
  DMA 到 sound RAM → 串 `01 80 <addrHi> <addrLo> 05 01 01 00`
  （cmd1 啟動 ch0 指向剛載入的資料 + cmd5）。
- 音樂載入 `$2996`：先送 cmd2×8 停全部通道，等 `$0270` 區清 0，
  再把歌曲資料的位址表複製到 65C02 **`$8400`**，並依 header 中的
  （目的位址, 來源, 長度）列表逐段 DMA 進 sound RAM。

### 4.2 取樣資料的 68k 端供應 (a)

- 取樣播放是 **68k DMA 到 sound RAM + 65C02 設 UM6619 播放** 的分工。
- Boom Zoo 常式 `$28A6`：d0 低 byte=取樣編號、d0 高 byte bit0-2=槽位，
  槽位目的位址表（`$28F4`）：**`$8BC0`、`$EB00`、`$EC40`、`$ED80`、`$EEC0`**
  （5 個 PCM 緩衝）；DMA 後送 cmd1 啟動對應通道。
- Speedy 常式 `$3536`：歌曲載入，兩段 DMA（目的 `$8C00` 與 header 指定
  位址）；`$35BA` 把 0x800 bytes 標頭 DMA 到 `$8400`。

### 4.3 latch 通道（`$0404/$0405` → 3-byte 封包）(a，語意部分待查證)

- 兩個 latch 各自收 3-byte 封包（`$F53F`/`$F4F1`），存 `$0241–$0243`，
  收滿由 `$F5D5` 解碼：
  - byte0 bit0-1（含符號擴充）<<8 + byte1 → 累加進 `$0248/$0249,y`
    （16-bit）；
  - byte0 bit2-3 <<8 + byte2 → 累加進 `$025C/$025D,y`；
  - byte0 bit4-5 → `$0244,y`；
  - y=0（`$0404`）或 2（`$0405`），即兩組獨立通道。
- 形式像兩組 10-bit 帶符號數值 + 2-bit 欄位的即時控制（音高滑音/音量？），
  **確切語意待查證**。68k 端經 `$E80404/$E80405` 窗口寫入（寫入即置位並
  觸發 IRQ bit3/bit2；65C02 讀取即 ack 並清空，空讀回 `$CD`）。
  另注意 `$E90004/$E90005` 不是這條 latch 的 68k 端：它是 68k 讀取 `$040C/$040D`
  的取樣 DMA 位址回報埠（memory-map.md §2.1）。

### 4.4 取樣 DMA 完成 IRQ 與雙緩衝 (a)

- UM6619 取樣播放完成 → 65C02 IRQ bit6 → `$F64A`：讀 reg `$16`，
  遞減 `$36/$37` 長度計數，重寫 regs（表 `$F6C9`）：reg `$7F` 在
  `$30/$38` 間切換（**bit3 = 緩衝半頁選擇**）；接近播完時寫
  `$040D=0`、`$040C=$8C/$8E`（依半頁）、`$040A=$FF` 通知 68k
  IRQ6 來 refill 下一段——**雙緩衝 PCM 串流**。
- 對應 MAME (b)「取樣 DMA 位址由 65C02 經 host port 交給 68k」的機制。

## 5. UM6619 暫存器語意

> (a) 從驅動碼歸納；2026-08-31 起經 superacan-emu 實作驗證，與 MAME
> `umc6619_sound.cpp` (b) 模型一致處已標註。

**合成模型（(b)+(a) 實作驗證）**：16 通道 PCM 取樣，取樣 = 共享 sound RAM
的 8-bit **無號**資料（讀出後 −128 <<8 成 16-bit）；通道位址以 16.16 固定
小數點遞增（addr_increment = period << 6，每個 native 取樣點前進）；
原生抽樣率 = **3.579545 MHz / 80 = 44744.3125 Hz**（MAME：`clock/16/5`）。
無 FM 式 operator 寫入跡象。

| Reg | 語意 |
|---|---|
| `$07` | 初始化寫 `$80`（全域控制？） |
| `$11/$12` | **timer period**（(b)）：實際 period = `10 × (0x10000 − ($12$11))` clocks；初始值 `$02F9` → 約 200 Hz（音樂 tempo） |
| `$13` | 初始化 `=$90`（待查證） |
| `$14` 的**寫入**也會 ack | Bcan 的 65C02 匯流排寫入端（`sub_1400A5220`）：資料 ≤ `$3F` 且暫存器號為 `$14` 時，清掉內部 IRQ 旗標的 bit7 並重算 pending。也就是說 timer IRQ 除了讀 `$14` 之外，**寫一個 ≤ `$3F` 的值進 `$14` 同樣會 ack**（(a)） |
| `$14` | timer/IRQ 控制：寫入 bit7 啟動/重載 timer；bit6 致能到期觸發 65C02 IRQ bit7；**讀取 = ack timer IRQ**（(b)，與驅動 tick 行為一致） |
| `$16` | 取樣 DMA 狀態/控制：讀 bit6=busy、**讀取 = ack DMA IRQ（bit6）**；寫 `$80` 啟動、寫 0 停止。MAME 的寫入語意更明確：`m_dma_channels = data << 8`，即以 bitmask 選擇 DMA 驅動通道，只涵蓋 ch8–15（寫 `$80` = ch15），與驅動只用 ch15 播取樣一致 |
| `$17` | **key on/off**：寫 `ch`（key-off）或 `ch|$10`（key-on），低 4 bit=通道；(b)：高 nibble ≠0 即 key-on。key-on 時 curr=start<<6、end=curr+length |
| `$20–$2F` | 通道 0–15 period 低 byte（addr_increment 低半） |
| `$30–$3F` | 通道 period 高 byte（cmd3 取樣位址借用 `$2F/$3F`，即 ch15 的 period——取樣播放實為 ch15 以 DMA 模式播放 (b)） |
| `$40–$4F` | 通道模式/控制。**bit1 ＝ 包絡開關**（見 §5.2）；音樂通道初始化寫 3、取樣串流通道寫 1 |
| `$50–$5F` | **波形長度/屬性**（(b)）：length = `0x40 << ((data & $0E) >> 1)`；bit0 = one-shot（播完停，否則 loop）。驅動 cmd3 的 `$5F=$06` → length 0x100 |
| `$60–$6F`/`$70–$7F` | **取樣起始位址**高/低 byte（(b)：16-bit 值 ×0x40 = 實際 sound RAM 位址）；`$7F` bit3=雙緩衝半頁選擇（與 (a) §4.4 一致） |
| `$8C/$8E` | 經 `$040C` 交給 68k 的取樣位址值（非直接寫 UM6619） |
| `$90–$9F` | **DMA 驅動旗標**（(b)「register9」）：非 0 的通道播到 end 時觸發 65C02 IRQ bit6 並自動重新 key-on——雙緩衝串流（`$9F=$FF` 即 ch15 取樣播放） |
| `$A0–$DF` | **每通道 ADSR 包絡參數**：`$A0`=attack、`$B0`=decay、`$C0`=第二段衰減、`$D0`=sustain 位準＋release（見 §5.2）。MAME 只存不用 |
| `$AF/$EF` | 初始化 `=$80/$FF`（主音量/混音？待查證） |
| `$E0–$EF` | **通道音量**：高 nibble 左、低 nibble 右。展開方式兩個模擬器不同——MAME ×17 線性、Bcan 走非線性查表（見 §5.3）。驅動每拍依 `$02F0,ch` 與主音量 `$42` 重算寫入，fade 用 |

合成方式判斷：**PCM/取樣為主**——音樂通道靠 period（`$20/$30`）+ 音量
（`$E0`）+ key 控制（`$17`），SFX 另走 DMA 取樣播放（`$16/$9F` + 雙緩衝）。
superacan-emu 依此模型實作後三款遊戲（Boom Zoo/Monopoly/Speedy Dragon）
音樂皆正常（數值驗證見 superacan-emu/docs/verify-audio-input.md）。

### 5.2 包絡產生器（`confirmed-Bcan`，2026-09-02）

`$40` 與 `$A0/$B0/$C0/$D0` 這幾組先前標成「待查證」的暫存器，是一套**每通道 ADSR 包絡**。
語意來自 Bcan 的 `sub_1400A7D80`（狀態進入）與 `sub_1400A8880`（每取樣更新），
暫存器對應由 `sub_1400A4190`（暫存器寫入分派）確認。MAME 只把 `$A0–$DF` 存進
`envelope[4]` 欄位，從未使用；本專案目前也沒有實作。

增益是 24 位元小數（`0x1000000` ＝ 1.0），在音量 nibble 之後再乘一次。

| 暫存器 | 欄位 | 作用 |
|---|---|---|
| `$40+ch` | bit1 | **包絡開關**。key-on 時 bit1 為 1 且 `$90+ch` 為 0 才進 attack；取樣串流通道寫 `$01`（bit1 清除）完全不走包絡 |
| `$A0+ch` | bits 4–0 | **attack**：時間 ≈ `(32 − n) × 取樣率 ÷ 500` 個取樣（n=0 約 64 ms），線性上升到 1.0。**n = 31 表示跳過 attack** |
| `$B0+ch` | bits 4–0 | **decay**：時間 ＝ `取樣率 × 6 ÷ n` 個取樣（`$D0` bit7 設起時係數改 2.5），走平方曲線降到 sustain。n = 0 表示不衰減 |
| `$C0+ch` | bit3、bits 2–0 | **第二段衰減**：bit3 開關、低 3 位速率，時間 ＝ `8 × 取樣率 ÷ n`，每取樣乘 `exp2(−8 ÷ 時間)` |
| `$C0+ch` | bits 4–3 | 參與 sustain 目標位準的取值方式 |
| `$D0+ch` | bits 7–4 | **sustain 位準**：目標 ＝ `v << 20`（v/16）。v 依 `$D0` bit7 與 `$C0` bits 4–3 取 `(高 nibble)+1` 或 `(高 nibble) XOR $F` |
| `$D0+ch` | bits 3–0 | **release**：key-off 後時間 ＝ `取樣率 × 256 ÷ 2^n` 個取樣，幾何衰減。n = 0 表示不釋放 |

曲線三種：attack 線性、decay 平方（`(t²) >> 24`）、第二段衰減與 release 是幾何。

**key-off 不是立即停聲**：`$17` 寫入高 nibble 為 0 時，若該通道的包絡狀態不是 0 或 6，
Bcan 進 release 態而不是關掉通道。MAME 的 key-off 直接清 active 位元，
兩者對尾音的處理完全不同。

⚠ 這一節是 **Bcan 的實作**，不是實機驗證。但它的形狀（`exp2`、6000／2500／500／8 這些
常數、`(32−n)` 的 attack 表達式）看起來是照著某份資料寫的，不像隨手發明。

#### 5.2.1 遊戲寫入值的佐證（a）

把三款遊戲跑到音樂播放中，從存檔狀態讀出 UM6619 的 256 個暫存器現值，再用 §5.2 的公式
換算成時間。結果支持這套解讀：

| 音色 | `$A0` | `$B0` | `$C0` | `$D0` | attack | decay | 第二段 | sustain | release |
|---|---|---|---|---|---|---|---|---|---|
| Speedy ch0–2 | `0C` | `0F` | `08` | `88` | 40 ms | 167 ms | 關 | 9/16 | 1000 ms |
| Speedy ch3/8 | `10` | `15` | `00` | `6B` | 32 ms | 286 ms | 關 | 9/16 | 125 ms |
| Speedy ch4/5 | `1F` | `00` | `0F` | `77` | 跳過 | 不衰減 | 1143 ms | 8/16 | 2000 ms |
| Speedy ch6 | `1F` | `00` | `00` | `0F` | 跳過 | 不衰減 | 關 | 15/16 | 8 ms |
| Boom Zoo 主音色 | `0E` | `01` | `06` | `57` | 36 ms | 6000 ms | 關 | 10/16 | 2000 ms |
| Boom Zoo ch2/10 | `1F` | `00` | `01` | `0A` | 跳過 | 不衰減 | 關 | 15/16 | 250 ms |
| Monopoly ch0 | `1A` | `16` | `09` | `AD` | 12 ms | 114 ms | 8000 ms | 11/16 | 31 ms |
| Monopoly ch1 | `17` | `19` | `09` | `68` | 18 ms | 240 ms | 8000 ms | 9/16 | 1000 ms |
| Monopoly ch2/7 | `1F` | `00` | `00` | `0A` | 跳過 | 不衰減 | 關 | 15/16 | 250 ms |

四項證據：

1. **閘門條件對得上。** 三款的每一個音樂通道都寫 `$40 = $03`（bit1 設起），而 Monopoly
   的取樣串流通道 ch15 寫 `$40 = $01` 且 `$90 = $FF`——正是模型要求的「串流通道不走包絡」。
   MAME 原始碼那句沒有解釋的註解（`Normally 0x03 for keyon channels, 0x01 for streaming
   DMAs`）在這個模型下才有原因。
2. **`$A0 = $1F` 的特例被實際使用，而且用得一致。** 12 組音色裡有 5 組是 `$1F`（跳過
   attack），這 5 組**同時**都是 `$B0 = 0`（不衰減）配短 release——打擊樂／點狀音效的
   標準設定。欄位若解錯，不會出現這種聚集。
3. **換算出的時間全在音樂範圍內**：attack 12–44 ms、decay 114 ms–6 s、release 8 ms–2 s。
4. **同一組參數在多個通道重複**（Boom Zoo 有 9 個通道共用 `0E 01 06 57`），
   是「一個音色定義套到多個聲部」的樣子。

唯一的例外是 Monopoly ch6 的 release（`$D0` 低 nibble ＝ 2 → 換算 64 秒），數值上不合理。
可能是閒置通道，也可能表示 release 的換算係數不對——**單筆例外不足以推翻，也不該掩蓋**。

這一節佐證的是**欄位語意**（哪個位元是開關、哪個 nibble 是哪一段、`$1F` 的特例），
不是那些時間常數（500、6000／2500、8、256）。常數換成別的比例會得到整體縮放不同、
但同樣「看起來合理」的結果，所以常數仍然只有 Bcan 一個來源。

重現方式：跑到音樂播放中存一個 state，用 `machine.ParseSaveState` 讀出
`Audio.Registers`（`[256]uint8`）即可。本專案的 headless 工具目前沒有內建音效暫存器
傾印（`--video-registers` 只涵蓋 UM6618），是個可以補的小功能。

#### 5.2.2 結案狀態

欄位語意（開關位元、四段參數的分配、`$A0 = $1F` 的特例、key-off 進 release）由 Bcan 反編譯
加三款遊戲的實際寫入值雙向支持，視為定案。**時間常數（500、6000／2500、8、256）與音量
查表只有 Bcan 一個來源**，維持 `confirmed-Bcan`，要往上推需要實機——這一項已接受為現況，
不列為進行中的工作。真的取得實機時，`§5.2.1` 的換算表就是第一份對照清單。

### 5.3 音量 nibble 的展開兩邊不同（`confirmed-Bcan`）

`$E0+ch` 的高／低 nibble 經一張 16 項查表得到左右聲道音量，**不是 MAME 的 ×17**：

```text
Bcan：0 51 68 102 119 136 153 153 170 187 204 204 221 238 238 255
×17： 0 17 34  51  68  85 102 119 136 153 170 187 204 221 238 255
```

Bcan 的表在低音量端陡得多（nibble 1 就到 51），中段有三處平台，只有 0 與 15 與線性版本
相同。表的來源不明，**哪一版對應實機待查證**；本專案目前跟隨 MAME，所以同一份音樂在
兩邊的音量平衡必然不同。

## 6. 68k 端觸發/等待範式

- 送命令：寫 `$E80300+` 命令串 → `move.b d0,$E9000A` → 輪詢
  `$E80300==$FF`（Speedy `$28DE` 帶 0xC000 次逾時 + 定時呼叫 `$34C6`）。
- 65C02→68k：65C02 寫 `$040A` → 68k IRQ6；68k 直接從 sound RAM
  （`$0200/$0202` 手把、`$0270` 通道狀態等）讀狀態，無額外握手。
