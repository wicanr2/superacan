# 68k IPL（internal_68k.bin）反組譯分析

> 來源：**(a)** 級——`Bcan008b/bios/supracan.zip` 內 `internal_68k.bin`
> 先做 16-bit 位元組交換（word-swap，見 [bios-rom-format.md](bios-rom-format.md)）
> 後以 GNU objdump（m68k:68000）反組譯（2026-08-30）；對照 MAME
> `src/mame/umc/supracan.cpp`、`src/mame/umc/umc6650.cpp` **(b)**。
> 依工作守則只記位址、暫存器操作與流程，不複製大段反組譯或版權資料。

## 1. 檔案佈局（word-swap 還原後）

| Offset | 內容 |
|---|---|
| `$000–$3FF` | 向量表與填充。向量 0（SSP）= `$00FD000A`、向量 1（PC）= `$00000400`；其餘多數指向 `$00000622`（共用的單一 `RTE`） |
| `$400–$630` | 程式碼（全部 IPL 邏輯，約 560 bytes） |
| `$632–$947` | `0xFFFF` 填充 |
| `$948` | ASCII 字串 `UMC 1994 (C)` |
| `$954` 起 | 128 byte（64 word）授權比對表——與卡帶 offset `$2000` 的資料逐字比對；表內嵌明文 `(reverse engineer)`（原廠留給逆向者的彩蛋/警告） |
| `$9D4–$FFF` | 雜湊/校驗用資料表（供 `$2000` 區第二階段校驗） |

## 2. IPL 流程

1. **Reset**：SSP=`$FD000A`、PC=`$400`（取自本 ROM 向量表）。
2. **`$400`**：`NOP` 後 `JSR $40A` 進入安全檢查常式。`$406` 的
   `JSR (SP)`/`RTS` 在正常流程下不會執行到（檢查常式不返回），屬死碼/欺敵。
3. **`$40A`：UMC6650 安全晶片檢查**（細節見 §3）。
4. **`$554` 起：卡帶授權資料檢查**（細節見 §4）。
5. **`$5F4`**：把 `$0100` 推入堆疊（SSP 仍為 `$FD000A`，用途待查證，
   可能是欺敵），清 `$E90B3C`，`JMP $F80604`（高區視圖的本 ROM `$604`）。
6. **`$604`：轉交控制權給卡帶**：
   - 對 `$E9001C`（sound CPU / lockout 控制暫存器）先 OR `$0002`、再 OR
     `$0008`（bit1、bit3）。對照 MAME 註解（(b)）：bit1 = loview lockout、
     bit3 = hiview lockout 方向——即**關閉 BIOS overlay、切換到卡帶視圖**。
   - `MOVEA.L ($0),SP`、`MOVEA.L ($4),A0`：overlay 關閉後 `$0/$4` 已是
     **卡帶**向量表 → 重新載入 SSP 與 PC。
   - `JMP (A0)` → 進入卡帶入口（各遊戲入口見 bios-rom-format.md §2.1）。
   - 全程**未動 bit0（sound reset）**：65C02 保持 HALT，由卡帶程式自行
     上傳代碼並釋放（見 [bios-65c02.md](bios-65c02.md)）。
   - IPL **完全不初始化** UM6618/調色盤/VRAM；只與 UMC6650、`$E90B3C`
     （雜訊區）、`$E9001C` 三個硬體位址互動。

## 3. UMC6650 協定（(a)，由 IPL 反組譯推得）

IPL 使用兩個埠：`A0=$EB0D03`、`A1=$EB0D01`。依操作順序可判定：

- **`$EB0D03`（寫）= 內部位址埠**（設定晶片內部 7-bit 位址）
- **`$EB0D01`（讀/寫）= 資料埠**（對當前內部位址讀寫）
- 內部空間：`$20–$2F` = 16 byte 唯讀金鑰（即 `umc6650.bin` 內容：
  ASCII `UMC 1994 (C)` + 4 byte 校驗 `90 70 65 9B`）；`$40–$5F` = 32 byte RAM；
  `$09`、`$0C` = 輸出到卡帶的 lockout 結果暫存器（MAME TODO 亦提到 cart
  B26/B27 來自 `$09`）。

> **與 MAME 的差異（待查證）**：MAME `umc6650.cpp` 的 read/write 把
> offset 1 當位址埠、offset 3 當資料埠，**與 IPL 實際用法相反**；MAME 能
> 開機可能依賴 §3.1 失敗路徑最終仍放行，或其「externalized key」處理。
> Bcan（需要 umc6650.bin）應是按正確順序實作。

### 3.1 IPL 的檢查步驟（`$40A`–$553）

1. 讀 `$E90B3C`（雜訊區）`& 1`，奇數則回寫——無害試探。
2. **RAM 區測試**：位址 `$5F` 遞減到 `$40`：先讀出 32 byte 舊值暫存於
   Work RAM `$FC0000`，再逐位址寫入等於位址的值並讀回比對（驗證 RAM
   可讀寫），最後把舊值還原。每步之間穿插對 `$E90B3C` 寫入變化值
   （`$C170`、`$B5D8`、`$B971`、`$A46C`…——MAME 標為 nopr 的雜訊）。
3. **金鑰讀回**：位址 `$2F` 遞減到 `$20`，把 16 byte 金鑰以**反向順序**
   讀入 Work RAM。
4. **金鑰驗證**：
   - 對緩衝區做四種校驗和（byte 加總 d4、byte 減總 d5、word 加總 d6、
     word 減總 d7），與金鑰尾 4 byte（`90 70 65 9B`）比對——即這 4 byte
     是 ASCII 字串的校驗值。
   - 逐 word 比對緩衝區尾端應為 `UM`、`( `、`)C`（即金鑰開頭反向）。
5. **寫出 lockout 結果**：內部暫存器 `$09 ← $FF`、`$0C ← $00`（輸出給
   卡帶側 B26/B27）。
6. **失敗路徑** `$548`：`DBLE D4` 的 dbcc 迴圈跳回校驗碼中段——行為依
   當時旗標而定、最壞情況為長延時懲罰迴圈；是否最終仍放行開機
   **待查證**（明顯是反逆向混淆寫法）。

## 4. 卡帶授權檢查（`$554`–`$5F3`，類似 Sega TMSS）

- **第一階段**：`CMPM` 逐 word 比對卡帶 ROM `$2000` 起 64 word（128 byte）
  與 IPL 內部 `$954` 的表；不符跳失敗路徑。
- **第二階段**：以 `MULS` 為主的雜湊迴圈（外層 20×、中層 16 word、內層
  16 次，帶符號/進位累積）對卡帶 `$2000` 區再算兩組校驗值，與 IPL 內部
  表（`$9D4` 起）比對。
- 實測（(a)）：`Boom Zoo` 卡帶 offset `$2000` 的 128 byte 與 IPL `$954`
  表**完全一致**（含 `(reverse engineer)` 字樣）→ 所有正版卡帶都須內嵌
  這段授權資料才能過 BIOS。這也解釋了流通 ROM 在 `$2000` 附近有共同
  資料區塊。

## 5. 小結

- IPL 職責極單純：**UMC6650 主機側安全晶片交握 → 卡帶授權資料比對 →
  關閉 overlay 跳卡帶向量入口**。不做任何視訊/音效/RAM 初始化。
- 對 Bcan「bounded BIOS boot did not reach the cartridge entry」字串 (a)
  的對應：開機成功的判斷點就是走到 `$604`/`JMP (A0)`。
- 時脈：IPL 內**無**可依據的校準延時迴圈（`$548` 迴圈非校準用途），
  本次反組譯**沒有**為 68k 時脈（8.95 vs 10.74 MHz）提供新證據。
